## ТЕОРИЯ

### 1. Планиране на проекта — същност

**Проект** = ограничено от **времето и ресурсите** начинание за постигане на конкретен резултат.

**Характеристики:**
- **Temporality** — има начало и край
- **Uniqueness** — уникален резултат (нов продукт, знание, документ)
- **Progressive elaboration** — постепенно развитие

**Планът определя** как проектът се изпълнява, наблюдава, контролира и приключва.

#### Основни елементи на плана

| Елемент | Съдържание |
|---------|-----------|
| **Обхват (Scope)** | Всички задачи и дейности за постигане на целите |
| **График (Schedule)** | Контролни точки (milestones) + plan-графиk |
| **Разходи (Cost)** | Оценка на бюджет и ресурси |
| **Качество (Quality)** | Стратегия за гарантиране на качеството |
| **Подобряване на процесите** | Оптимизация на дейностите |
| **Човешки ресурси (Staffing)** | Брой и тип хора; набиране при нужда |
| **Комуникации** | Вътрешни + външни комуникации |
| **Риск** | Идентификация и управление на рискове |
| **Поръчки (Procurement)** | Доставки и договори |

---

### 2. Планиране на обхвата — WBS и контролни точки

#### Два вида обхват

| Вид | Описание |
|-----|---------|
| **Обхват на продукт** | Характеристики и функции на продукта/услугата |
| **Обхват на проект** | Работата, която трябва да се свърши |

#### Процеси по управление на обхвата

1. **Събиране на изисквания** — интервюта, фокус групи, brainstorming, анкети, прototips
2. **Дефиниране на обхвата (DECAA)**:
   - **D**escription — подробно описание на резултатите
   - **E**xclusions — какво НЕ е в обхвата
   - **C**onstraints — ограничения (бюджет, дати)
   - **A**ssumptions — предположения
   - **A**ctualisation — актуализации на документи

3. **WBS** — йерархична декомпозиция
4. **Верифициране** — формално приемане на резултатите
5. **Контрол** — следене на промени в обхвата

---

#### WBS (Work Breakdown Structure)

**WBS** = йерархична структура за разделяне на резултатите на по-малки, управляеми компоненти.

```
Проект "Онлайн магазин"
├── 1. Backend
│   ├── 1.1 API за продукти
│   │   ├── 1.1.1 GET /products
│   │   └── 1.1.2 POST /products
│   └── 1.2 API за поръчки
├── 2. Frontend
│   ├── 2.1 Начална страница
│   └── 2.2 Checkout flow
└── 3. Тестване
    ├── 3.1 Unit тестове
    └── 3.2 Integration тестове
```

**Работен пакет** (най-ниско ниво на WBS) съдържа:
- Описание на дейностите
- Зависимости от други пакети
- Acceptance criteria
- Изпълнител
- Оценка на ресурсите
- Срок

---

#### Контролни точки (Milestones)

**Контролна точка** = ключов момент, маркиращ началото/края на главна фаза.

**Видове:**
- **Основни** — маркират всяка фаза на жизнения цикъл
- **Второстепенни** — завършване на сложна дейност
- **Отчетни** — периодични прегледи / регулярни събития

**Рецепта за планиране:**
1. Общо съгласие за крайната цел
2. Brainstorming за варианти
3. Обсъждане и уточняване
4. Генериране на пътища към резултатите
5. Изчертаване на логическите зависимости
6. Построяване на окончателна схема

---

### 3. Планиране на ресурси и бюджет

#### Ресурси

| Вид | Примери |
|-----|---------|
| **Материални** | Хардуер, лицензи, офис пространство |
| **Нематериални (Човешки)** | Разработчици, тестери, PM |

**Стъпки за присвояване на цена на WBS пакет:**
1. Идентифицирай ресурси (материални + човешки)
2. Оцени времетраенето за всяка конфигурация
3. Изчисли цена = ресурс × продължителност
4. Приоритизирай конфигурациите
5. Избери оптималната

#### Бюджетни компоненти

- Разходи за персонал
- Разходи за оборудване/техника
- Пътни разходи
- Разходи за подизпълнители

#### Дейности по контрол

- **Мониторинг** — следене на изпълнение спрямо плана
- **Управление на промените** — обхват, идиректното, бюджет
- **Отчитане** — редовни доклади към ЗЛ
- **Решаване на проблеми**

### 4. Методи за план-график

#### Пет стъпки при изграждане на план-график:

1. Предварително времетраене на задачите
2. Идеален график по последователност
3. Идентификация на ресурси и работно време
4. Реално времетраене (с работни дни, празници)
5. Създаване/модификация на основния план-график

---

#### Метод на критичния път (CPM — Critical Path Method)

**Цел**: Намери **най-дългата последователност** от задачи (критичния път) — тя определя **минималната продължителност** на проекта.

**За всяка задача се дефинират:**

| Параметър | Означение | Описание |
|-----------|----------|---------|
| **Early Start** | ES | Най-ранно начало |
| **Early Finish** | EF | EF = ES + Duration |
| **Late Start** | LS | Най-късно начало без забавяне |
| **Late Finish** | LF | Най-късно завършване без забавяне |
| **Float (Slack)** | F | F = LS − ES = LF − EF |

**Критичен път** = пътят, за който **Float = 0** за всяка задача.

**Изчисление:**

**Forward pass** (ляво → дясно, намираме ES и EF):
- ES на начална задача = 0
- EF = ES + Duration
- ES на следваща = max(EF на всички предшественици)

**Backward pass** (дясно → ляво, намираме LF и LS):
- LF на последна задача = EF на последна
- LS = LF − Duration
- LF на предшественик = min(LS на всички наследници)

---

#### Метод PERT (Program Evaluation and Review Technique)

**Цел**: Оценка на времетраенето при **неопределеност**.

$$T_{expected} = \frac{T_{optimistic} + 4 \times T_{most\_probable} + T_{pessimistic}}{6}$$

| Оценка | Описание |
|--------|---------|
| **T_optimistic** | Минимално реалистично време |
| **T_most_probable** | Най-вероятното реалистично |
| **T_pessimistic** | Максимално реалистично при неблагоприятни условия |

**Стандартно отклонение:**
$$\sigma = \frac{T_{pessimistic} - T_{optimistic}}{6}$$

**PERT + CPM**: Използваме PERT за оценка на продължителностите, след това прилагаме CPM.

---

#### GANTT Диаграма

**GANTT** = визуален инструмент за план-график; задачите се изобразяват като **правоъгълници** по оста на времето.

```
Задача          | Сед 1 | Сед 2 | Сед 3 | Сед 4 | Сед 5 | Сед 6 |
----------------|-------|-------|-------|-------|-------|-------|
1. Изисквания   |[=====]|       |       |       |       |       |
2. Дизайн       |       |[=====]|[=====]|       |       |       |
3. Backend      |       |       |[=====]|[=====]|[=====]|       |
4. Frontend     |       |       |       |[=====]|[=====]|       |
5. Тестване     |       |       |       |       |[=====]|[=====]|
```

**Предимства**: лесен за разбиране; показва паралелно изпълнение; показва зависимости.  
**Недостатъци**: При много задачи е труден за четене; не показва ресурси директно.

### Тип 1: Метод на критичния път (CPM)

**Дадено**: Задачи с продължителност и зависимости.

| Задача | Продължителност | Предшественици |
|--------|----------------|----------------|
| A | 3 | — |
| B | 4 | A |
| C | 2 | A |
| D | 5 | B |
| E | 3 | C |
| F | 2 | D, E |

**Стъпка 1 — Мрежова диаграма:**
```
Start → A → B → D → F → End
            ↘ C → E ↗
```

**Стъпка 2 — Forward Pass:**

| Задача | Duration | ES | EF |
|--------|---------|----|----|
| A | 3 | 0 | 3 |
| B | 4 | 3 | 7 |
| C | 2 | 3 | 5 |
| D | 5 | 7 | 12 |
| E | 3 | 5 | 8 |
| F | 2 | max(12,8)=12 | 14 |

**Стъпка 3 — Backward Pass:**

| Задача | Duration | LF | LS | Float |
|--------|---------|----|----|-------|
| F | 2 | 14 | 12 | 0 ✓ |
| D | 5 | 12 | 7 | 0 ✓ |
| E | 3 | 12 | 9 | 4 |
| B | 4 | 7 | 3 | 0 ✓ |
| C | 2 | 9 | 7 | 4 |
| A | 3 | 3 | 0 | 0 ✓ |

**Критичен път**: **A → B → D → F** (Float = 0)  
**Продължителност на проекта**: **14 дни**

---

### Тип 2: PERT оценка

**Дадено**: T_opt = 3, T_prob = 5, T_pess = 10

$$T_{exp} = \frac{3 + 4 \times 5 + 10}{6} = \frac{3 + 20 + 10}{6} = \frac{33}{6} = 5.5 \text{ дни}$$

$$\sigma = \frac{10 - 3}{6} = \frac{7}{6} \approx 1.17$$
