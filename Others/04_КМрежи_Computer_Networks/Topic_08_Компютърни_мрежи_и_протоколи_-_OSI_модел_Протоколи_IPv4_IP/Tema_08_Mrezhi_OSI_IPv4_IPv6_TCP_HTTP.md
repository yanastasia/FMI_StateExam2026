# Тема 8: Компютърни мрежи и протоколи – OSI модел. Протоколи IPv4, IPv6, TCP, HTTP.

---

## ТЕОРИЯ

### 1. OSI модел — 7 нива

| № | Ниво | Единица данни | Функция | Примери |
|---|------|--------------|---------|---------|
| 7 | **Application** (Приложен) | Данни | Интерфейс към приложенията; протоколи за услуги | HTTP, FTP, SMTP, DNS |
| 6 | **Presentation** (Презентационен) | Данни | Кодиране, декодиране, криптиране, компресия | SSL/TLS, ASCII, JPEG |
| 5 | **Session** (Сесиен) | Данни | Създаване, поддържане, прекратяване на сесии; автентикация | NetBIOS, RPC |
| 4 | **Transport** (Транспортен) | Сегмент | Надеждна/ненадеждна доставка между крайни точки; сегментиране | TCP, UDP |
| 3 | **Network** (Мрежови) | Пакет | Маршрутизация между мрежи; логическа адресация | IP, ICMP, маршрутизатор |
| 2 | **Data Link** (Канален) | Кадър (Frame) | Безгрешно предаване между съседни устройства; MAC адресиране | Ethernet, Wi-Fi, Switch |
| 1 | **Physical** (Физически) | Бит | Предаване на битове по физически носител; синхронизация | NIC, кабел, хъб, модем |

**Мнемоника**: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing ↕ **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way

### 2. Съпоставяне OSI ↔ TCP/IP

```
OSI (7 нива)              TCP/IP (4 нива)
┌──────────────┐          ┌─────────────────────┐
│ 7 Application│          │                     │
│ 6 Presentation│ ───────▶│    Application       │
│ 5 Session    │          │ (HTTP, FTP, DNS…)   │
├──────────────┤          ├─────────────────────┤
│ 4 Transport  │ ───────▶│    Transport         │
│              │          │ (TCP, UDP)          │
├──────────────┤          ├─────────────────────┤
│ 3 Network    │ ───────▶│    Internet          │
│              │          │ (IP, ICMP)          │
├──────────────┤          ├─────────────────────┤
│ 2 Data Link  │ ───────▶│    Network Access   │
│ 1 Physical   │          │ (Ethernet, Wi-Fi)   │
└──────────────┘          └─────────────────────┘
```

**Разлики:**
- OSI = теоретичен модел; TCP/IP = практически стандарт (базата на Интернет)
- TCP/IP обединява OSI 5+6+7 → Application; OSI 1+2 → Network Access
- OSI не е директно имплементиран; TCP/IP е световен стандарт

### 3. IPv4 адресация

**IPv4 адрес**: 32 бита, записан като 4 октета в десетичен вид, разделени с точки.  
Пример: `192.168.1.100`

#### Класова адресация

| Клас | Диапазон (1-ви октет) | Prefix | Subnet маска | Мрежи | Хостове/мрежа |
|------|----------------------|--------|-------------|-------|---------------|
| **A** | 1–127 | /8 | 255.0.0.0 | 2⁷−2 = 126 | 2²⁴−2 |
| **B** | 128–191 | /16 | 255.255.0.0 | 2¹⁴ | 2¹⁶−2 |
| **C** | 192–223 | /24 | 255.255.255.0 | 2²¹ | 2⁸−2 = 254 |
| **D** | 224–239 | — | — | Multicast | — |
| **E** | 240–255 | — | — | Резервирани | — |

> −2 при хостовете: мрежовият адрес (всички 0) и broadcast адресът (всички 1) са запазени.

**Фиксирани префикси:**
- Клас A: MSB = `0` (0xxxxxxx)
- Клас B: MSB = `10` (10xxxxxx)
- Клас C: MSB = `110` (110xxxxx)
- Клас D: MSB = `1110`

**Резервирани адреси:**
| Адрес | Значение |
|-------|---------|
| `0.0.0.0` | Маршрут по подразбиране |
| `127.0.0.1` | Localhost (loopback) |
| `255.255.255.255` | Limited broadcast |
| `192.168.x.x`, `10.x.x.x`, `172.16–31.x.x` | Частни (RFC 1918) |

#### Безкласова адресация (CIDR)

**CIDR** (Classless Inter-Domain Routing) — по-гъвкаво разпределение чрез произволна дължина на маската.

Формат: `адрес/префикс` — напр. `192.168.1.0/24`

`/24` = 24 бита за мрежа, 8 бита за хостове → 254 хоста

**Пресмятане:**
- Брой хостове = 2^(32−префикс) − 2
- Subnet маска = 32 бита, първите `n` са 1, останалите 0
- `/24` → `11111111.11111111.11111111.00000000` = `255.255.255.0`

**Пример:** `10.0.0.0/22`
- 32−22 = 10 бита за хостове → 2¹⁰−2 = 1022 хоста
- Маска: `/22` = `255.255.252.0`

### 4. IPv6 — основни характеристики

**Защо IPv6?** IPv4 адресите са изчерпани (~4.3 млрд). IPv6 не е обратно съвместим с IPv4.

| Характеристика | IPv4 | IPv6 |
|---------------|------|------|
| Дължина на адрес | 32 бита | **128 бита** |
| Нотация | Десетична с точки | Шестнадесетична с двоеточия |
| Брой адреси | ~4.3 × 10⁹ | ~3.4 × 10³⁸ |
| Header | Сложен (опции) | **Опростен** (фиксирани полета) |
| NAT | Необходим | **Не е необходим** (всеки хост има уникален адрес) |
| Автоконфигурация | DHCP | **SLAAC** (без DHCP) |
| Сигурност | IPsec — незадължителен | **IPsec — вграден** |
| Мобилност | Ограничена | Поддържана |
| Broadcast | Да | **Не** (заменен с Multicast и Anycast) |

**Формат на IPv6 адрес:** 8 групи × 4 hex цифри, разделени с `:`  
Пример: `2001:0db8:9095:02e5:0216:cbff:feb2:7474`

**Съкращения:**
- Водещи нули в група се пропускат: `0db8` → `db8`
- Една последователност от нулеви групи → `::` (само веднъж)
- `::1` = loopback (0:0:0:0:0:0:0:1)

**Структура на адреса:**
```
| Мрежов префикс (48b) | Subnet ID (16b) | Host ID (64b) |
```

### 5. TCP — процедура на трикратно договаряне (Three-Way Handshake)

TCP е **надежден**, **ориентиран към връзка** транспортен протокол.

#### Установяване на връзка:

```
Клиент                              Сървър
  │                                   │
  │──── SYN (seq=x) ─────────────────▶│   Клиентът предлага начален seq номер x
  │                                   │
  │◀─── SYN+ACK (seq=y, ack=x+1) ────│   Сървърът потвърждава (ack=x+1) и предлага y
  │                                   │
  │──── ACK (ack=y+1) ───────────────▶│   Клиентът потвърждава (ack=y+1)
  │                                   │
  │════════ DATA TRANSFER ════════════│
```

**SYN** = Synchronize Sequence Number  
**ACK** = Acknowledgement

#### Прекратяване на връзка (Four-Way Handshake):
```
Клиент          Сървър
  │──── FIN ────▶│
  │◀─── ACK ────│
  │◀─── FIN ────│
  │──── ACK ────▶│
```

#### TCP vs UDP:

| | TCP | UDP |
|-|-----|-----|
| Връзка | Ориентиран (handshake) | Без връзка |
| Надеждност | Гарантирана доставка | Без гаранции |
| Ред | Запазен | Не е гарантиран |
| Скорост | По-бавен | По-бърз |
| Употреба | HTTP, FTP, SMTP | DNS, стрийминг, VoIP |

### 6. HTTP — Хипертекстов протокол

**HTTP** = Приложен слой; клиент-сървър протокол; работи върху TCP, порт **80** (HTTPS → **443**).

**Комуникация:** Request (клиент → сървър) + Response (сървър → клиент)

#### HTTP методи:

| Метод | Действие | Данни |
|-------|---------|-------|
| **GET** | Извлича ресурс | В URL |
| **POST** | Изпраща данни към сървъра | В тялото на заявката |
| **PUT** | Заменя ресурса изцяло | В тялото |
| **PATCH** | Частично модифицира ресурса | В тялото |
| **DELETE** | Изтрива ресурса | — |
| **HEAD** | Като GET, но само headers (без body) | — |
| **OPTIONS** | Връща поддържаните методи за URL | — |
| **TRACE** | Тест на пътя (echo) | — |

#### HTTP статус кодове:

| Диапазон | Категория | Примери |
|---------|-----------|---------|
| **1xx** | Информационни | 100 Continue |
| **2xx** | Успешни | 200 OK, 201 Created, 204 No Content |
| **3xx** | Пренасочвания | 301 Moved Permanently, 302 Found, 304 Not Modified |
| **4xx** | Клиентски грешки | 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found |
| **5xx** | Сървърни грешки | 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable |

#### Структура на HTTP Request:
```
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
[празен ред]
[тяло — само при POST/PUT/PATCH]
```

#### Структура на HTTP Response:
```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1234
[празен ред]
<html>...</html>
```

#### HTTP версии:

| Версия | Ключова характеристика |
|--------|----------------------|
| HTTP/1.0 | Нова TCP връзка за всяка заявка |
| HTTP/1.1 | Persistent connections (keep-alive); pipelining |
| HTTP/2 | Мултиплексиране на заявки; бинарен протокол; Server Push |
| HTTP/3 | Върху QUIC (UDP); по-малко latency |

| Понятие | Ключ |
|---------|------|
| OSI слой 1 | Physical — битове по носител |
| OSI слой 2 | Data Link — MAC адреси, кадри |
| OSI слой 3 | Network — IP, маршрутизация |
| OSI слой 4 | Transport — TCP/UDP, сегменти |
| OSI слой 7 | Application — HTTP, DNS, FTP |
| TCP/IP слоеве | 4: Network Access, Internet, Transport, Application |
| IPv4 | 32 бита, 4 октета, ~4.3 млрд адреса |
| Клас A | 1–127, /8, 16M хоста |
| Клас B | 128–191, /16, 65K хоста |
| Клас C | 192–223, /24, 254 хоста |
| CIDR /n | 2^(32-n) - 2 хоста |
| IPv6 | 128 бита, hex с `:`, вграден IPsec, без NAT |
| TCP handshake | SYN → SYN+ACK → ACK |
| HTTP порт | 80 (HTTP), 443 (HTTPS) |
| GET vs POST | GET: данни в URL; POST: данни в тялото |
| 404 | Not Found; 500 = Server Error; 200 = OK |
